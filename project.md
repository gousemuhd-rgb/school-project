Project: College Complaint Management System1. Project Overview & Tech StackProject OverviewBuild a full-stack College Complaint Management System that allows students to easily submit and track issues (e.g., infrastructure, academic, administrative), while providing college staff and administrators a centralized platform to assign, update, and resolve these complaints. The system must support role-based access control, status tracking, and a clean, responsive UI.Tech StackFrontend: Next.js (Pages Router), React, Tailwind CSS, Zustand (for state management), Axios, and lucide-react icons.  Backend: Node.js, Express, MongoDB, Mongoose, JSON Web Tokens (JWT), bcryptjs for password hashing, helmet, cors, and express-validator.  Deployment Architecture: Frontend deployed to Vercel, Backend deployed to Render, Database hosted on MongoDB Atlas, and source code versioned on GitHub.  2. Authentication, Users, and RolesAuthenticationThe system must support user registration and login using email and password.  JWT-based session handling with password hashing (bcrypt at cost factor 12).  Persistent login state on the client using Zustand.  RolesStudent: Can create new complaints, view their own complaint history, and add comments to their active tickets.Staff: Can view complaints assigned to their specific department, update complaint statuses, and communicate with students via comments.Admin: Can manage all users, assign complaints to specific staff/departments, and view college-wide analytics.3. Core Features & Business LogicComplaint Submission: Students must be able to create a complaint by specifying a Title, Category (e.g., Maintenance, IT, Academic, Hostel), Description, and Urgency Level.Status Tracking: Every complaint must cycle through defined statuses: PENDING, IN_PROGRESS, RESOLVED, or REJECTED.Communication Thread: A commenting system must exist on each complaint detail page for transparent communication between the student and staff.Dashboard Metrics: Visual representation of active vs. resolved complaints (for admins and staff).4. Frontend PagesThe frontend uses the Next.js Pages Router with the following routes:  / – Landing page introducing the system with login/register CTA buttons.  /login – Form for email/password authentication with validation and error states.  /register – Form for user registration.  /dashboard – Role-based operator console. Students see their active tickets; Staff see assigned department tickets; Admins see system-wide metrics and a master list.  /complaints/new – Form for students to submit a new complaint./complaints/[id] – Detailed view of a specific complaint, showing status badges, metadata, and the comment thread.  /admin/users – Admin-only portal to manage user roles and departmental assignments.5. Backend Architecture & Database CollectionsArchitectureRoutes: Handles HTTP routing and middleware composition (auth, validation, error handler).  Controllers: Responsible for request parsing and response shaping only.  Services: Owns the business logic (complaint CRUD, status transition rules, user management).  Database CollectionsUsers: Stores authenticated users (name, email, password with select: false, role: student | staff | admin, department).  Complaints: Stores the tickets (title, description, category, urgency, status, createdBy, assignedTo, createdAt, updatedAt).Comments: Stores conversation threads (complaintId, userId, message, createdAt).6. API EndpointsAuth & UsersPOST /api/auth/register – Register a new user account.  POST /api/auth/login – Authenticate user and issue JWT.  GET /api/auth/me – Fetch current user profile.  GET /api/users – List users (Admin only).ComplaintsGET /api/complaints – List complaints (Logic: Admins see all, Students see own, Staff see assigned).POST /api/complaints – Create a new complaint.GET /api/complaints/:id – Fetch single complaint details.  PUT /api/complaints/:id/status – Update existing complaint status (Staff/Admin only).  POST /api/complaints/:id/comments – Add a comment to a specific complaint.7. UI, Security, Outcome, and Antigravity InstructionsUI and UX RequirementsThe UI must use a clean aesthetic with Tailwind CSS, be fully responsive, and include loading states and skeleton loaders.  Use distinct visual status badges for complaints (e.g., Red for PENDING, Yellow for IN_PROGRESS, Green for RESOLVED).Security RequirementsHash passwords with bcrypt at cost 12.  Sign and verify JWTs using JWT_SECRET stored in environment variables.  Apply CORS rules, validate request bodies using express-validator, and set HTTP security headers via helmet.  Credentials must never be hardcoded. Always use environment variables (e.g., process.env.MONGODB_URI).  AI Agent (Antigravity) Implementation InstructionsBuild the application phase by phase.
